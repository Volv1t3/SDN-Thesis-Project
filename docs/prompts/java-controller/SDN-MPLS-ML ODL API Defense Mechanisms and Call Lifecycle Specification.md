# SDN-MPLS-ML ODL API Defense Mechanisms and Call Lifecycle Specification

## 1. Purpose

This document defines the required defense mechanisms, retry behavior, idempotency rules, polling loops, response handling, and tunnel lifecycle state machine for the SDN-MPLS-ML Java ODL controller.

The controller must not treat ODL/PCEP/NETCONF API calls as simple synchronous transactions. The validated behavior of this lab requires treating the ODL workflow as **eventually consistent** across:

```text id="vuctup"
ODL RESTCONF data tree
ODL RPC operations
PCEP session state
Cisco XR auto-PCC tunnel creation
Cisco XR NETCONF-mounted operational data
Cisco XR interface configuration datastore
```

Therefore, every critical ODL operation must follow this general pattern:

```text id="g9kpu4"
send API request
→ parse response
→ classify response as success / provisional success / ambiguous / hard failure
→ poll authoritative operational endpoint
→ update registry only after confirmation
```

---

## 3. Global Response Classification Model

All ODL calls must classify responses into one of four categories.

```java id="hni3zm"
public enum OdlCallOutcomeType {
    CONFIRMED_SUCCESS,
    PROVISIONAL_SUCCESS,
    AMBIGUOUS,
    HARD_FAILURE
}
```

### 3.1 Confirmed Success

Use only when the response itself proves the requested state is complete.

Examples:

```text id="za165f"
Topology endpoint returns HTTP 200 and required topology IDs exist.
BGP-LS topology returns HTTP 200 and required router IDs resolve.
Loopback0 patch returns HTTP 204 No Content or any HTTP 2xx.
```

Even with confirmed success, tunnel operations still require operational polling afterward.

---

### 3.2 Provisional Success

Use when the API accepted the operation, but device state still needs to be verified.

Examples:

```text id="d7uzsa"
add-lsp returns HTTP 200 with no failure.
add-lsp returns HTTP 200 with <failure>no-ack</failure>.
update-lsp returns HTTP 200 with no failure.
update-lsp returns HTTP 200 with <failure>no-ack</failure>.
```

Provisional success must always transition into polling.

---

### 3.3 Ambiguous

Use when the controller cannot determine whether ODL or XR applied the operation.

Examples:

```text id="qt03co"
HTTP timeout after request was sent.
Connection reset after request was sent.
HTTP 500 from NETCONF mount during an eventually consistent operation.
Empty body from an RPC expected to return XML.
```

Rule:

```text id="w03wvv"
For ambiguous add-lsp/update-lsp outcomes:
  poll operational state first.
  retry second.
```

---

### 3.4 Hard Failure

Use when the operation clearly failed and should not be retried blindly.

Examples:

```text id="266jg9"
401/403 authentication failure
malformed XML generated by the controller
missing required topology
missing configured router ID
path-computation status != completed
add-lsp returns HTTP 200 with failure other than no-ack
update-lsp returns HTTP 200 with failure other than no-ack
classifier response missing required policy fields
```

## 4. Global Retry Policy

### 4.1 Default Retry Configuration

```text id="4of9r0"
initialDelayMs = 500
maxDelayMs = 5000
jitterPercent = 20
defaultTimeoutSeconds = 120
```

Recommended environment variables:

```text id="5az71s"
ODL_RETRY_INITIAL_DELAY_MS=500
ODL_RETRY_MAX_DELAY_MS=5000
ODL_RETRY_JITTER_PERCENT=20
ODL_TUNNEL_DISCOVERY_TIMEOUT_SECONDS=120
ODL_OPERATIONAL_VALIDATION_TIMEOUT_SECONDS=120
ODL_TOPOLOGY_DISCOVERY_MAX_ATTEMPTS=5
```

---

### 4.2 Exponential Backoff

Pseudo-code:

```java id="utbs57"
Duration delay = Duration.ofMillis(initialDelayMs);

while (!timeoutExpired()) {
    attempt();

    if (success) {
        return result;
    }

    sleep(withJitter(delay));

    delay = min(delay * 2, maxDelay);
}
```

Jitter rule:

```text id="yitg0x"
actualDelay = delay ± jitterPercent
```

Example:

```text id="poevhk"
500 ms
1000 ms
2000 ms
4000 ms
5000 ms
5000 ms
...
```

---

### 4.3 Retryable Conditions

Retryable:

```text id="a4sggv"
HTTP 404 when waiting for newly created tunnel interface to appear
HTTP 409 datastore/config conflict
HTTP 500 transient NETCONF/device commit issue
HTTP timeout
connection reset
empty body from an eventually consistent operational endpoint
tunnel not found yet after add-lsp provisional success
tunnel found but still not operational after Loopback0 patch
```

---

### 4.4 Non-Retryable Conditions

Do not retry blindly:

```text id="lgly23"
authentication failure
authorization failure
invalid environment configuration
missing required topology ID
missing configured router ID in BGP-LS topology
malformed XML
path-computation status != completed
path-computation response has no path-description
add-lsp hard failure
update-lsp hard failure
```

## 5. Idempotency Rules

## 5.1 General Rule

Before creating or updating state, always check whether the intended state already exists.

```text id="c6rcub"
read current state
→ compare desired state
→ call mutation endpoint only if required
```

---

## 5.2 add-lsp Idempotency Rule

`add-lsp` is dangerous because repeated calls may create duplicate auto-PCC tunnels.

Before calling `add-lsp`:

```text id="su0cxg"
1. Check TunnelRegistry by directionKey.
2. If usable tunnel exists, do not call add-lsp.
3. Poll tunnel-heads by symbolicTunnelName.
4. If matching tunnel already exists, adopt it into TunnelRegistry.
5. Only call add-lsp if no local registry entry and no remote tunnel-head match exist.
```

After ambiguous `add-lsp` result:

```text id="54adj3"
Do not immediately retry add-lsp.
Poll tunnel-heads first.
If tunnel exists, continue workflow.
If tunnel does not exist after discovery timeout, allow one controlled retry.
```

---

## 5.3 update-lsp Idempotency Rule

Before calling `update-lsp`:

```text id="e4m0hu"
1. Require usable tunnel in TunnelRegistry.
2. Compare desired ERO against active cached ERO.
3. Compare desired bandwidth against active cached bandwidth.
4. If no change, skip update-lsp.
```

Do not call `update-lsp` when:

```text id="1r7m8r"
no tunnel record exists
tunnel interface name is unknown
Loopback0 patch has not succeeded
tunnel is not operational
symbolic tunnel name is unknown
PCC node is unknown
```

Never fall back from failed `update-lsp` to `add-lsp`.

```text id="8r717b"
update-lsp failure must not create a duplicate tunnel.
```

## 7. State Machine Flow for Initial Tunnel Creation

### 7.1 Normal Initial Creation Flow

```text id="4ngqdm"
NO_TUNNEL
→ PRE_DISCOVERY_PENDING
→ PRE_DISCOVERY_NOT_FOUND
→ ADD_LSP_PENDING
→ ADD_LSP_PROVISIONAL_SUCCESS
→ TUNNEL_DISCOVERY_PENDING
→ TUNNEL_INTERFACE_DISCOVERED
→ LOOPBACK_PATCH_PENDING
→ LOOPBACK_PATCHED
→ OPERATIONAL_VALIDATION_PENDING
→ USABLE_FOR_UPDATE
```

---

### 7.2 Existing Tunnel Adoption Flow

If the controller restarts but the tunnel already exists on XR:

```text id="95qgmi"
NO_TUNNEL
→ PRE_DISCOVERY_PENDING
→ PRE_DISCOVERY_FOUND_EXISTING
→ TUNNEL_INTERFACE_DISCOVERED
→ LOOPBACK_PATCH_PENDING if needed
→ OPERATIONAL_VALIDATION_PENDING
→ USABLE_FOR_UPDATE
```

This prevents unnecessary `add-lsp` calls after controller restart.

---

### 7.3 Ambiguous add-lsp Flow

```text id="22xee4"
ADD_LSP_PENDING
→ ADD_LSP_AMBIGUOUS
→ TUNNEL_DISCOVERY_PENDING
```

If tunnel appears:

```text id="8vcej3"
TUNNEL_DISCOVERY_PENDING
→ TUNNEL_INTERFACE_DISCOVERED
→ LOOPBACK_PATCH_PENDING
```

If tunnel never appears:

```text id="5ulmo1"
TUNNEL_DISCOVERY_PENDING
→ TUNNEL_DISCOVERY_TIMEOUT
→ controlled add-lsp retry, if retry budget remains
```

---

### 7.4 Hard Failure Flow

```text id="016bll"
ADD_LSP_PENDING
→ ADD_LSP_HARD_FAILURE
```

Do not continue to Loopback0 patch.

Do not create static routes.

Do not mark tunnel reusable.

---

## 8. State Machine Flow for Tunnel Updates

### 8.1 Normal Update Flow

```text id="2b5trm"
USABLE_FOR_UPDATE
→ UPDATE_LSP_PENDING
→ UPDATE_LSP_PROVISIONAL_SUCCESS
→ UPDATE_VALIDATION_PENDING
→ UPDATE_VALIDATED
→ USABLE_FOR_UPDATE
```

---

### 8.2 Ambiguous Update Flow

```text id="b6kdhb"
UPDATE_LSP_PENDING
→ UPDATE_LSP_AMBIGUOUS
→ UPDATE_VALIDATION_PENDING
```

If the tunnel operational state reflects the desired update:

```text id="ymnxi0"
UPDATE_VALIDATION_PENDING
→ UPDATE_VALIDATED
→ USABLE_FOR_UPDATE
```

If no change is observed after timeout:

```text id="7t4gt1"
UPDATE_VALIDATION_PENDING
→ UPDATE_VALIDATION_FAILED
```

Then retry `update-lsp` only if retry budget remains.

Do not call `add-lsp`.

---

### 8.3 Hard Update Failure

```text id="i3unab"
UPDATE_LSP_PENDING
→ UPDATE_LSP_HARD_FAILURE
```

Required behavior:

```text id="c3xloj"
keep existing tunnel record
mark update failed
do not delete tunnel
do not call add-lsp
do not mark new ERO as active
```

## 9.5 add-lsp RPC

### Endpoint

```http id="ebm352"
POST {ODL_RESTS_OPERATIONS_BASE_URL}/network-topology-pcep:add-lsp
```

Concrete lab path:

```http id="mu91lx"
POST http://172.21.121.100:8181/rests/operations/network-topology-pcep:add-lsp
```

### Purpose

Create an auto-PCC RSVP-TE tunnel on the PCC router.

### Call Guard

Before calling `add-lsp`, perform:

```text id="fh11eh"
1. Check TunnelRegistry by directionKey.
2. If usable tunnel exists, return it.
3. Poll tunnel-heads by symbolicTunnelName.
4. If tunnel exists remotely, adopt it.
5. Only call add-lsp if no usable local tunnel and no remote tunnel match exist.
```

### Request Body

```xml id="uai0a0"
<?xml version="1.0" encoding="UTF-8"?>
<input xmlns="urn:opendaylight:params:xml:ns:yang:topology:pcep">
    <node>${pccNode}</node>
    <name>${symbolicTunnelName}</name>
    <arguments>
        <path-setup-type>
            <pst>rsvp-te</pst>
        </path-setup-type>

        <lsp>
            <lsp-flags>
                <delegate>true</delegate>
                <administrative>true</administrative>
            </lsp-flags>
        </lsp>

        <bandwidth>
            <bandwidth>${bandwidthBytesPerSecondFloat}</bandwidth>
        </bandwidth>

        <endpoints-obj>
            <ipv4>
                <source-ipv4-address>${sourceRouterId}</source-ipv4-address>
                <destination-ipv4-address>${destinationRouterId}</destination-ipv4-address>
            </ipv4>
        </endpoints-obj>

        <ero>
            ${eroSubobjects}
        </ero>
    </arguments>

    <network-topology-ref xmlns:nt="urn:TBD:params:xml:ns:yang:network-topology">
        /nt:network-topology/nt:topology[nt:topology-id="${pcepTopologyId}"]
    </network-topology-ref>
</input>
```

### Response Handling

Classify response as follows:

```text id="7plfk7"
HTTP 200 + no <failure>:
  PROVISIONAL_SUCCESS

HTTP 200 + <failure>no-ack</failure>:
  PROVISIONAL_SUCCESS

HTTP 200 + <failure>anything-else</failure>:
  HARD_FAILURE

HTTP 4xx:
  HARD_FAILURE unless proven transient

HTTP 5xx:
  AMBIGUOUS for first occurrence
  poll tunnel-heads before retrying

timeout after request sent:
  AMBIGUOUS
  poll tunnel-heads before retrying
```

### Critical no-ack Rule

```text id="xgfrbo"
<failure>no-ack</failure> is not treated as final failure.
It is treated as provisional success.
The controller must continue to tunnel-head discovery.
```

### Post-add-lsp Mandatory Action

After `PROVISIONAL_SUCCESS` or `AMBIGUOUS`:

```text id="kssqz8"
poll tunnel-heads by symbolicTunnelName
```

Do not patch Loopback0 until tunnel interface is discovered.

Do not mark tunnel usable until Loopback0 is patched and operational state is validated.

```

```

Concrete LSR4 path:

```http id="ut1ner"
GET http://172.21.121.100:8182/restconf/data/network-topology:network-topology/topology=topology-netconf/node=sma-xrv-lsr4-delta/yang-ext:mount/Cisco-IOS-XR-mpls-te-oper:mpls-te/p2p-p2mp-tunnel/tunnel-heads?content=all
```

### Purpose

Discover the generated auto-PCC tunnel interface and validate operational state.

### Matching Order

Match tunnel records using this priority:

```text id="r6at71"
1. auto-pcc symbolic name == requested symbolicTunnelName
2. signalled-name == requested symbolicTunnelName
3. config/signalled-name == requested symbolicTunnelName
4. tunnel-interface-name == known tunnelInterfaceName, only after registry exists
```

### Required Extracted Fields

```text id="4g1028"
tunnelInterfaceName
tunnelId
plspId if present
signalledName
configSignalledName
autoPccSymbolicName
operationalState
pathState
signallingState
failReason
currentPath if present
```

### Discovery Success Condition

```text id="ixzwur"
matching symbolic tunnel found
AND tunnelInterfaceName extracted
```

### Operational Success Condition

```text id="l6wum2"
matching symbolic tunnel found
AND tunnelInterfaceName exists
AND operationalState indicates up
AND signallingState indicates connected
AND failReason is absent or non-fatal
```

### Discovery vs Operational State

The controller must distinguish:

```text id="matks6"
discovered:
  tunnel exists and tunnel-teXYZ is known

usable:
  tunnel exists, Loopback0 patched, operational up, signalling connected
```

A discovered tunnel is not automatically usable.

## 9.8 update-lsp RPC

### Endpoint

```http id="umujv9"
POST {ODL_RESTS_OPERATIONS_BASE_URL}/network-topology-pcep:update-lsp
```

Concrete lab path:

```http id="2tn3u0"
POST http://172.21.121.100:8181/rests/operations/network-topology-pcep:update-lsp
```

### Purpose

Update the path of an existing PCC tunnel using the cached symbolic tunnel name and newly computed ERO.

### Call Guard

Only call `update-lsp` if:

```text id="8jwxnt"
TunnelRegistry has a record for directionKey
symbolicTunnelName exists
pccNode exists
tunnelInterfaceName exists
loopback0Patched == true
usableForUpdate == true
tunnel operational state is up
new ERO differs from active ERO OR bandwidth differs from active bandwidth
```

Do not call `update-lsp` if:

```text id="kg92ua"
no tunnel exists
tunnel is only partially discovered
Loopback0 patch failed
tunnel is operational-down
symbolic name is missing
computed path failed
```

### Recommended Request Body

Baseline validated shape:

### Response Handling

```text id="au7y2m"
HTTP 200 + no <failure>:
  PROVISIONAL_SUCCESS

HTTP 200 + <failure>no-ack</failure>:
  PROVISIONAL_SUCCESS

HTTP 200 + <failure>anything-else</failure>:
  HARD_FAILURE

HTTP 4xx:
  HARD_FAILURE unless known transient

HTTP 5xx:
  AMBIGUOUS
  poll tunnel-heads before retrying

timeout after request sent:
  AMBIGUOUS
  poll tunnel-heads before retrying
```

### Post-update Mandatory Action

After `PROVISIONAL_SUCCESS` or `AMBIGUOUS`:

```text id="s7h14b"
poll tunnel-heads
verify tunnel still exists
verify operational state remains up
verify signalling remains connected
update active ERO only after validation
```

Never call `add-lsp` because `update-lsp` failed.

## 10. Continuous Calling Mechanisms

## 10.1 Startup Continuous Discovery

At startup:

```text id="17s0c9"
1. Read topology list.
2. Read BGP-LS topology.
3. Build router-id → graph node ID registry.
4. Validate headend and tailend router IDs.
5. Start PacketReceived processing only after validation.
```

Retry startup discovery only for transient HTTP/network failures.

Fail startup for logical failures.

---

## 10.2 Topology Refresh Loop

Background loop:

```text id="jqsue1"
Every TOPOLOGY_CACHE_TTL_SECONDS:
  read BGP-LS topology
  rebuild candidate registry
  validate headend/tailend still resolve
  if valid, replace active registry
  if invalid, keep last known good registry and mark stale
```

Defense rule:

```text id="yrfkxc"
Never replace a valid registry with an invalid or incomplete one.
```

---

## 10.3 Tunnel Discovery Polling Loop

After `add-lsp`:

```text id="cg3998"
while timeout not expired:
  GET tunnel-heads
  find symbolicTunnelName
  if found and tunnelInterfaceName exists:
      return discovered tunnel
  sleep with exponential backoff
```

Timeout behavior:

```text id="bv7a6z"
mark TUNNEL_DISCOVERY_TIMEOUT
do not patch Loopback0
do not mark tunnel usable
```

---

## 10.4 Loopback Patch Retry Loop

After tunnel interface discovery:

```text id="8n0cy2"
while timeout not expired:
  PUT Loopback0 patch
  if HTTP 2xx:
      mark patch successful
      return
  if retryable:
      sleep with exponential backoff
  else:
      fail hard
```

After success:

```text id="bsjm4g"
poll tunnel-heads for operational validation
```

---

## 10.5 Operational Validation Loop

After Loopback0 patch or update-lsp:

```text id="6ofxit"
while timeout not expired:
  GET tunnel-heads
  find symbolicTunnelName
  check operational state
  check signalling state
  check fail reason
  if usable:
      mark USABLE_FOR_UPDATE
      return
  sleep with exponential backoff
```

Timeout behavior:

```text id="swgfqi"
mark OPERATIONAL_VALIDATION_FAILED
do not mark tunnel usable
```

---

## 10.6 Update Validation Loop

After `update-lsp`:

```text id="ph6bx9"
while timeout not expired:
  GET tunnel-heads
  find symbolicTunnelName
  verify tunnel remains up
  optionally verify path changed if operational data exposes current path
  if validated:
      update active ERO in TunnelRegistry
      return
  sleep with exponential backoff
```

If path cannot be directly verified from tunnel-heads:

```text id="wt28du"
minimum validation:
  tunnel still exists
  operational state up
  signalling connected
  fail reason absent

then mark update as provisionally validated
```

## 11. Registry Update Rules

## 11.1 TunnelRegistry Update Rules

Do not insert a tunnel as usable immediately after `add-lsp`.

Use staged fields:

```text id="thfkzr"
symbolicTunnelName known:
  after request construction

tunnelInterfaceName known:
  after tunnel-head discovery

tunnelId known:
  after tunnel-head discovery

plspId known:
  after tunnel-head discovery, if available

loopback0Patched=true:
  after Loopback0 PUT returns HTTP 2xx

usableForUpdate=true:
  after operational validation succeeds
```

---

## 11.2 Active Path Update Rule

Only update active ERO/bandwidth in the registry after:

```text id="3mcrqq"
update-lsp response is provisional success or confirmed success
AND tunnel-head validation succeeds
```

Do not update active path after:

```text id="8rzv6n"
update-lsp hard failure
update-lsp ambiguous response without validation
validation timeout
```

---

## 11.3 Classification Cache Rule

Classifier result may be cached after successful classifier response.

Do not cache:

```text id="w3h4zy"
failed classifier responses
malformed classifier responses
fallback guesses not returned by classifier
```

---

## 11.4 Path Cache Rule

Path computation may be cached after:

```text id="277zn4"
HTTP 200
status completed
path-description count > 0
ERO translation succeeds
```

Do not cache:

```text id="xv2d6t"
failed path computation
empty path
malformed XML
status not completed
```

## 12. Endpoint Outcome Matrix

| Operation | Confirmed Success | Provisional Success | Ambiguous | Hard Failure |
|---|---|---|---|---|
| Topology list GET | HTTP 200 + required topology IDs | n/a | timeout / transient 5xx | missing required topology / auth failure |
| BGP-LS topology GET | HTTP 200 + head/tail RIDs resolve | n/a | timeout / transient 5xx | RID missing / conflicting graph IDs |
| Classifier POST | HTTP 200 + valid prediction/policy | n/a | timeout | malformed response / unavailable with no fallback |
| Path computation POST | HTTP 200 + status completed + path entries | n/a | timeout / transient 5xx | status not completed / no path |
| add-lsp POST | n/a | HTTP 200 no failure or failure=no-ack | timeout / 5xx after send | failure other than no-ack |
| Tunnel-head GET | HTTP 200 + matching tunnel state found | tunnel exists but not operational yet | timeout / transient 5xx | malformed XML / auth failure |
| Loopback0 PUT | HTTP 2xx | n/a | timeout / transient 5xx | malformed XML / invalid tunnel interface |
| update-lsp POST | n/a | HTTP 200 no failure or failure=no-ack | timeout / 5xx after send | failure other than no-ack |

## 17. Final Rule Summary

The controller must obey these hard rules:

```text id="zdk4l2"
1. Never hardcode path-computation graph node IDs.
2. Never call add-lsp if a usable tunnel already exists.
3. Never immediately retry add-lsp after timeout; poll first.
4. Treat add-lsp no-ack as provisional success.
5. Never patch a guessed tunnel-te interface.
6. Never mark tunnel usable before Loopback0 patch and operational validation.
7. Never call update-lsp without a usable cached tunnel.
8. Treat update-lsp no-ack as provisional success.
9. Never fall back from failed update-lsp to add-lsp.
10. Never update active tunnel path cache until post-update validation succeeds.
```

The intended resilient lifecycle is:

```text id="m5vkg4"
discover topology
→ resolve router IDs
→ classify packet
→ compute path
→ pre-discover tunnel
→ add-lsp only if absent
→ poll tunnel-heads
→ patch Loopback0
→ validate operational state
→ cache usable tunnel
→ use update-lsp for future path changes
→ poll and validate after every update
```
